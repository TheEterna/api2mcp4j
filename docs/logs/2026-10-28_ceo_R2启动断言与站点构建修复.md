### 一、R2 启动断言（V-2 缺口）

#### 缺口现场（代码核实，非文档转述）

| 事实 | 位置 |
|---|---|
| `ParserCondition` 只做「配置里有没有这个名字」的比对 | `autoconfigure/.../conditional/Conditions.java:62-95` |
| `PluginProperties` 标了 `@ConfigurationProperties` + `@Component`，但其包不在用户组件扫描路径内，全仓无 `@EnableConfigurationProperties` 引用它 | → **枚举的强校验从未生效** |
| 对比：`scope` 走 `environment.getProperty(..., ScopeType.class, ...)`，**有**枚举转换；`parser` 走 `String[]`，**完全绕过**枚举 | 两处不一致 |

即：把 `JAVADOC` 拼成 `JAVADOCS`，该解析器静默不激活、启动零告警，运行时才发现工具描述缺失或参数 Schema 退化。

#### 实施时对方案的两处优化

| 项 | 原方案 | 实际 | 理由 |
|---|---|---|---|
| 已知名权威源 | `ParserNames` 常量类持有两个 `Set` | **权威改为 `PluginProperties` 的两个枚举**，`ParserNames` 是其注解侧镜像 | 实施时发现那两个枚举本就存在且属配置契约；`@ConditionalOnParser` 的 value 必须是编译期常量（`Enum.name()` 不满足），故仍需常量层，但权威应归枚举 |
| 散落定义 | 仅改 `McpConfig` | 另改 `Conditions.ParserCondition` 两处默认数组 | 同一批解析器名此前在 **3 处**各写一遍，任一处漏改即漂移 |

#### 落地内容

- `ParserNames`（新增）：7 个常量 + `DES_NAMES`/`PARAM_NAMES`
- `ParserNameValidator`（新增，`ApplicationRunner`）：默认 WARN / strict 时抛 `IllegalStateException`；匹配规则与 `ParserCondition` 的 `equalsIgnoreCase` 一致（避免「校验器说不合法、条件判定却能命中」的矛盾）

### 二、F3 · Javadoc 解析器零开销短路

**背景**：`JavaDocDesParser` 已 `@Deprecated`（作者原话：「javaParser 只能针对 java 源文件，jar 包启动时没有 java 文件，会直接导致报错」），但**仍在默认描述解析链里** → 每个下游用户的每个工具方法都白跑一次 `getResourceAsStream("xxx/Xxx.java")`（Spring Boot fat-jar 嵌套结构下并不廉价），必然失败，必然返回 null。

**方案调整**：初版拟「从默认链移除 JAVADOC」，**否决** —— 那会连带损失开发环境（IDE / `target/classes` 下源码可读）的 Javadoc 描述能力，得不偿失。改为**源码不可读时短路**：

- 新增 package-private `isSourceReadable(Class)`：依据类的加载位置做启发式判定，无法判定时保守返回 false（宁可跳过，不可误报）
- `doDesParse` 入口短路，不再触发 classloader 查找
- 顺带给 `getJavaSourceFile` 补 Javadoc（该方法此前无文档注释）

**测试调整**：RED 阶段用 Mockito mock `java.lang.Class` 不可行（Mockito 明确禁止 mock Class），改为锁定两条**行为契约**：jar 加载 → 短路返回 null 不抛异常；**开发环境 → Javadoc 解析能力不受影响**（短路改动的主要回归风险点）。

### 四、文档站：构建失败 + 两处定义根治

#### 4.1 构建此前必然失败 🔴

```
[vite:vue] logs/2026-08-05_ceo_隐私审计.md (268:53):
Error parsing JavaScript expression: Unexpected token (1:9)
```

**根因**：08-05 隐私审计日志含 GitHub Actions 语法 `${{ secrets.* }}`。VitePress 把 Markdown 渲染结果当作 **Vue 模板**编译，Vue 模板编译器扫描文本节点里的 `{{` 并当作插值表达式求值 → `secrets.*` 不是合法 JS 表达式 → 报错 → **整站构建失败**。

**修法**：VitePress 1.6.4 无关闭 Vue 插值的官方开关（插值规则挂在 core 的 `text` 上，没有独立规则名可供 `md.disable`）。改用 Vue 的 **`v-pre`** 指令（元素级跳过插值解析）：

```js
md.renderer.rules.code_inline = (tokens, idx) =>
  `<code v-pre>${md.utils.escapeHtml(tokens[idx].content)}</code>`;
```

**实测产物**：`<code>${{ secrets.* }}</code>` 原样呈现，72 个页面构建通过。

#### 4.2 「同一文档两处定义」—— 四个月对外失真的根因 🔴

`docs-site/` 下的 `docs/` `logs/` `reference/` `rules/global/` `specs/` `index.md` `zh-cn/` 全部是 `../docs/` 与 `../README*.md` 的**镜像副本**（由 `scripts/build-docs.sh` 生成），**却被 git 跟踪** —— 同一文档两处定义，任一处漏改即漂移。

**实际后果**：2026-08-04 → 2026-10-28 期间，`docs/` 的全部更新都没进站点：七篇工作日志、三份计划、架构总览的协议层章节（`core/spec/` 十二能力域）全部缺席。**对外可见的文档站在展示四个月前的架构描述**。

**根治**：
- 镜像路径 `git rm --cached` + 写入 `docs-site/.gitignore`（保留 `.vitepress/config.mjs`、`package.json`、`_headers`、`_redirects`、`wrangler.toml`）
- 构建入口自洽：`package.json` 的 `docs:dev`/`docs:build` 均先跑 `build-docs.sh`；Cloudflare Pages 的构建命令本就含该步骤 —— **两处均无需人工同步**
- 导航改为**从目录动态生成**（`buildNavFrom`），日志与计划自动出现，倒序（新的在前）—— 此前手工维护、只列到 08-03

## 发现

### F1 · F2「配置类解析阶段 getBean」在当前架构下无法简单修复 🟡 已记录不改

`McpToolScanRegistrar` 在配置类解析阶段直接 `beanFactory.getBean(IToolContext.class)`，是 Spring 反模式（该 bean 无法被常规后置处理器处理）。

**复核结论：不改**。原因：`ClassPathToolScanner` 的构造器需要**持有已实例化的** `IToolContext`（其内部 `ToolBeanNameGenerator.generateBeanName` 在扫描过程中就要调 `toolContext.addTool(...)`）。即「扫描前必须已实例化」是**当前架构的硬约束**，改成 `RuntimeBeanReference` 延迟引用会 NPE。彻底修法需把「注册」与「扫描」解耦（扫描时只收集 bean 名，容器就绪后再注册），涉及注册时序重构 —— 协议层改动，风险收益比不划算。

可见症状已由 `proxyBeanMethods = false` 消除（见 2026-10-28 日志《下游启动日志降噪》），当前**无功能风险**。

### F2 · Mockito 不能 mock `java.lang.Class` 🟢 已换方案

RED 阶段原打算 mock `Class` 来验证「不再触发 classloader 查找」，Mockito 明确拒绝（`Cannot mock/spy class java.lang.Class`）。改为锁定行为契约（jar 场景短路 / 开发环境不回归）—— **测行为而非实现细节**，反而更有价值。

### F3 · 站点部署仍缺凭据 🟡 待董事长

本机无 `wrangler` 命令、无 `~/.wrangler/config/default.toml` → **无法执行站点部署**。构建已修好、导航已自动化，凭据到位后一次部署即可让线上更新到当前状态。
