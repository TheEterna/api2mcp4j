# 发布路径复核与坐标迁移闭环报告

## 摘要

董事长答复「没 token」，借机把发布路径逐条对照 Sonatype 官方文档复核，推翻此前「代码侧 100% 就绪，唯一阻塞是 token」的判断：**实际还差命名空间认领**，且 token 是**两段独立值**而非一个字符串，另有发布插件配置自相矛盾。已把坐标由 `com.ai.plug` 迁移至 `io.github.theeterna`（32 处 / 12 个文件），修掉两处配置缺陷，并给发布自检加了第 10 组断言把这类问题变成机器可拦截的。**发布件仍待董事长提供「命名空间确认 + 两段 token」两项凭据。**

## 详情

### 一、命名空间：`com.ai.plug` 无法由本项目认领 🔴

| 事实 | 来源 |
|---|---|
| 认领命名空间须证明拥有其反向域名。官方原话：`com.example` → 检查 `example.com`，「不检查 com.example.com 或任何其他变体」 | https://central.sonatype.org/register/namespace/ |
| `com.ai.plug` 的反向域名落在 `ai.com` 名下 | 反向推导 |
| 本仓无董事长持有 `ai.com` 的迹象。已知持有 `xiaohan.chat`（NS = `junade.ns.cloudflare.com` / `reza.ns.cloudflare.com`） | `scripts/deploy-cf-pages.sh`；dns.google DoH 实测 |

**对既往结论的更正**：此前文档里「`com.ai.plug` 在 Central 未被占用」（search.maven.org numFound=0）只证明**无人发布过**，不证明**可被认领** —— 两件事。

**选定方案**：`io.github.theeterna`。官方对 GitHub 用户名的支持路径是「Sonatype can, in most cases, automatically verify and provision publishing access to a namespace that looks like `io.github.<your GitHub username>`」，无需 DNS。仓库 `TheEterna/api2mcp4j` 已确认为 public（GitHub 公共 API 实测），owner 即该账号。

### 三、User Token 是两段独立值 🔴

官方 `settings.xml` 片段：`<username>` 与 `<password>` 分别是 token 的 username 与 password 两个独立值（https://central.sonatype.org/publish/publish-portal-maven/ ）。

原 `settings.xml.example` 两处共用 `${env.CENTRAL_PORTAL_TOKEN}` → **即使拿到 token，上传必然鉴权失败**。已拆为 `CENTRAL_PORTAL_USERNAME` / `CENTRAL_PORTAL_PASSWORD`，`pre-release-check.sh` §7 与 `publish-to-central.sh` 头部注释同步。

### 四、发布插件配置自相矛盾 🟡

根 pom `central-publishing-maven-plugin` 原为 `<autoPublish>false</autoPublish>` + `<waitUntil>published</waitUntil>`。官方对后者的描述是「This requires Automatic Publishing」—— 两项直接冲突，且冲突时行为官方页**未描述**。

该路径只在 `deploy` 阶段触发，而此前所有验证（`mvn -Prelease clean verify`、`--dry-run`）都走不到 → **从未被实测过**。

已改 `waitUntil` 为 `validated`（官方默认值），**保留 `autoPublish=false`**：上传并通过校验后停在 Portal，由董事长到 Deployments 页点 Publish —— Maven Central 发布不可撤回，这道人工闸应当保留。

### 五、把这类问题变成机器可拦截的（TDD 双 commit）

`scripts/pre-release-check.sh` 新增**第 10 组「发布配置自洽」**：

| 断言 | 内容 |
|---|---|
| 10.1 | groupId 全仓一致：子模块 `<parent>` 必须与根 pom 一致；旧 groupId 残留检查**只针对本项目 artifactId**（pom 内 groupId 与 artifactId 必须紧邻配对；文档/脚本查「相邻 groupId」「X:server2mcp-*」「repository/X/server2mcp-*」三种形态），避免误伤第三方依赖与 Java 包名 |
| 10.2 | token 两段分离：`settings.xml.example` 的 `<username>` 与 `<password>` 不得指向同一变量 |
| 10.3 | 插件配置自洽：`autoPublish=false` 时 `waitUntil` 不得为 `published` |

**RED**（`66c8d74`）：10.2 与 10.3 报红；10.1 当前报绿（坐标尚未迁移，迁移后即为防漏改的门禁）。
**GREEN**（`4048c74`）：迁移坐标 + 修两处配置 → 全绿。

### 六、另更正一条无官方依据的旧结论

此前记录「注册 Central 时必须用同一个 noreply 邮箱，否则 Central 校验 GPG UID 与账号邮箱不匹配会拒收」。官方 GPG 要求页（https://central.sonatype.org/publish/requirements/gpg/ ）**未见**任何 UID/邮箱须与账号或 POM 开发者邮箱一致的要求；仅要求公钥分发到 keyserver（keyserver.ubuntu.com / keys.openpgp.org / pgp.mit.edu）并用主密钥签名。该说法已作废。
